## RESTful API & HTTP – Exam‑Prep Guide  

The following questions are grouped by topic and are designed to test recall, application, and deeper understanding of REST principles, HTTP methods, status codes, and best‑practice design.  
Duplicate items from the source material have been removed, and each question is phrased clearly in English.  Answers are included for self‑check but can be omitted if you prefer a blind‑test format.

---

### 1. Conceptual & Definition  

| # | Question | Suggested Answer |
|---|----------|------------------|
| 1 | What does **REST** stand for, and what is its primary design principle? | Representational State Transfer – a stateless, client‑server architecture that uses standard HTTP methods and status codes. |
| 2 | In a RESTful API, what is a **resource** and how is it uniquely identified? | Anything that can be addressed (user, product, document, etc.) identified by a unique URI. |
| 3 | What is meant by a **representation** of a resource? | The format in which the resource’s state is transferred (e.g., JSON, XML). |
| 4 | Explain **stateless communication** in the context of REST. | Each request contains all information needed; the server does not keep any session state between requests. |
| 5 | What are the five classes of HTTP status codes and what does each class represent? | 1xx – Informational, 2xx – Success, 3xx – Redirection, 4xx – Client Error, 5xx – Server Error. |
| 6 | Why should an API return an error status code when an operation fails? | To inform the client of the failure and allow it to handle the error appropriately. |

---

### 2. HTTP Methods & Idempotence  

| # | Question | Suggested Answer |
|---|----------|------------------|
| 7 | List the most common HTTP methods used in REST and state whether each is **idempotent**. | GET – Yes; POST – No; PUT – Yes; PATCH – Yes; DELETE – Yes |
| 8 | Define **idempotence** and give an example of how it applies to the `PUT` method. | A method is idempotent if multiple identical requests produce the same result. `PUT /users/123` with the same body always results in the same user state. |
| 9 | Which HTTP methods are considered **safe**, and what does “safe” mean? | GET, HEAD, OPTIONS – they should not modify server data. |
| 10 | Why is `POST` generally **not** idempotent? | Because each POST may create a new resource or have side‑effects that differ with each call. |
| 11 | If a client mistakenly sends a `POST` to a read‑only endpoint, which status code should the server return? | 405 Method Not Allowed |

### 4. Application & Scenario Questions  

| # | Question | Suggested Answer |
|---|----------|------------------|
| 35 | A client wants to update only the `email` field of a user. Which method should they use, and why? | `PATCH` – it partially updates the resource, sending only the modified field. |
| 36 | If a client repeatedly sends the same `DELETE /items/45` request, what will the server do and why? | It will delete the item on the first call and then return 404 on subsequent calls because the resource no longer exists; DELETE is idempotent. |
| 37 | Which HTTP method would you use to retrieve a list of products without changing any server state? | `GET` – safe and idempotent. |
| 38 | A client sends a malformed JSON body in a POST request. Which status code should the server respond with? | 400 Bad Request (malformed request body). |
| 39 | How can a client prevent unnecessary data transfer when checking if a resource has changed? | Use a conditional GET with headers like `If-Modified-Since` or `If-None-Match`; the server can respond with 304 Not Modified. |
| 40 | A user tries to create a new account with an email that already exists. What status code is appropriate? | 422 Unprocessable Entity – semantic error (duplicate email). |
| 41 | A client attempts to `DELETE /orders/123` but order `123` has already been shipped and is linked to a shipment record. Which status code is most appropriate? | 409 Conflict. |
| 42 | You receive a `405 Method Not Allowed` error when a client uses `PUT` on `/products/456`. What might be the cause, and how would you fix it? | The endpoint does not support `PUT`; either add support for `PUT` or instruct the client to use `PATCH` if partial update is intended. |
| 43 | During a maintenance window, your API is temporarily down. What status code should you return to clients, and what header can you include to inform them when the service will be available again? | 503 Service Unavailable with a `Retry-After` header. |
